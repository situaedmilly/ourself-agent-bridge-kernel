## 1. Core Amendment: Layer Nomenclature

### Previous (OMR-005 §14)
Observation Graph
- The model observes evidence streams.
- Observation is the act of witnessing.

### Amended (OMR-005.1)
Evidence Graph
- Observation is the **act**; evidence is what **persists**.
- Evidence Graph scales cleanly past ChatGPT (binary Yes/No veracity) to any corpus (probabilistic, multi-source, polyphonic signal).
- No foundational change to OMR-005 §5–§13 (authority classes, discovery rules, packet lifecycle, node/edge defaults).
- Only §14 (gate sequence) reorders.

### Why
Observation is ephemeral. Evidence is durable. As the Observation Graph was designed to accept any input corpus (Reddit, Discord, academic papers, filing cabinets, oral history), "Evidence Graph" is the correct name for the persistent, corpus-agnostic layer.

## 4. Node Defaults (D1–D4) – Ratified Unchanged

**D1: Atomicity**
- Every mention is a distinct atomic record (mention_id).
- No pre-merge of cross-type homonyms (e.g. "Smith" as person vs. "Smith" as company).
- 241 identified homonym pairs remain unmerged at node layer.

**D2: Observability**
- Every node must be traceable to source corpus entries.
- Nodes without source evidence are ephemeral scratch; may not be sealed.

**D3: Scope Binding**
- Nodes are scoped to their reference type (R0–R6).
- A person-node and a company-node may share a name; they remain distinct nodes.

**D4: Cross-Type Distinction**
- Togetherness across types (person—works-for—company) is expressed **only as edges**, never as node merging.

---

## 5. Edge Defaults & D5–D6 (CRITICAL AMENDMENT)

### D5: Firewall (OMR-005 §9, Restated)

**Weight is Evidence, Not Merge Authority**

- Edge weight = co-occurrence count, temporal proximity, source diversity, linguistic confidence.
- Edge weight is **never** a merge signal.
- Example: A —co-occurs(187)— B means "these appear together 187 times" — it is a **fact**, not permission to merge A and B.
- The firewall prevents graph collapse from correlation.

### D6: Full Provenance & Reproducibility (NEW — RATIFIED)

**Every Edge Is Regenerable from Corpus**

Every edge record must include and preserve:

| Field | Type | Purpose | Required |
|-------|------|---------|----------|
| edge_id | UUID | Unique edge identifier | Yes |
| source_node_id | UUID | Origin node | Yes |
| target_node_id | UUID | Destination node | Yes |
| relationship_type | enum | Edge class (e.g., co-occurs, works-for, authored) | Yes |
| weight | number | Primary signal (count, confidence, proximity score) | Yes |
| support_count | int | Number of independent corpus mentions | Yes |
| evidence_ids[] | UUID[] | Pointers to corpus entries that triggered this edge | Yes |
| source_system | string | Which extractor/observation layer produced this edge | Yes |
| first_observed | ISO-8601 timestamp | Earliest corpus evidence | Yes |
| last_observed | ISO-8601 timestamp | Most recent corpus evidence | Yes |
| extractor_version | string | Semantic version of the extractor that built this edge | Yes |

**Invariant:**
- Given the corpus and the extractor version, every field of an edge must be **deterministically regenerable**.
- No edge may exist whose provenance cannot be traced back to specific corpus entries.
- This ensures the graph is never "corrupted" by stale edges and remains auditable at every layer.

## 6. Acceptance Tests (10 Required)

These tests verify that OMR-006 EVIDENCE_GRAPH_ENGINE meets the addendum's architectural requirements.

### Test 1: Node Atomicity Preserved
- **Condition:** Ingest a corpus with 241 confirmed cross-type homonym pairs (same name, different entity type).
- **Expected:** All 241 pairs remain as distinct nodes.
- **Failure:** Any homonym pair is merged at node layer.

### Test 2: Edge Regenerability
- **Condition:** For every edge in the graph, extract edge.evidence_ids[] and regenerate the edge from those corpus entries using edge.extractor_version.
- **Expected:** All regenerated edges match the sealed edge (edge_id, weight, support_count, all fields identical).
- **Failure:** Any edge field diverges or evidence_ids are unfetchable.

### Test 3: Firewall Enforcement
- **Condition:** Two nodes A and B have an edge with weight=500 (high co-occurrence).
- **Expected:** Nodes remain distinct; no automatic merge is triggered.
- **Failure:** A and B are merged, deduped, or consolidated.

### Test 4: Source System Tracking
- **Condition:** Ingest from three systems: Reddit, Discord, Academic.
- **Expected:** Every edge records which system contributed (source_system field).
- **Failure:** source_system is null/empty or not tracked per-edge.

### Test 5: Temporal Boundaries
- **Condition:** Corpus spans 2020-01-01 to 2026-01-01.
- **Expected:** Every edge has first_observed and last_observed within that range.
- **Failure:** Any edge has a timestamp outside the corpus span.

### Test 6: Extractor Version Fidelity
- **Condition:** Use two versions of the extractor (v0.1.0 and v0.2.0) on the same corpus.
- **Expected:** All edges record their extractor_version; edges from v0.1.0 remain queryable and regenerable via v0.1.0.
- **Failure:** Extractor version is not recorded or edges become un-regenerable.

### Test 7: Evidence Array Non-Empty
- **Condition:** Query all edges in the graph.
- **Expected:** Every edge.evidence_ids[] contains at least one evidence ID.
- **Failure:** Any edge has an empty evidence_ids[] array.

### Test 8: No Pre-Merge Defaults
- **Condition:** Ingest a corpus with candidate nodes that share a name but have different reference types.
- **Expected:** Nodes are created as distinct mentions; no pre-merge logic creates a single "unified" node.
- **Failure:** Duplicate nodes or consolidated nodes appear in the graph.

### Test 9: Corpus-Bound Boundaries
- **Condition:** Corpus has entries A, B, C; no entry D exists.
- **Expected:** If D is inferred (transitive closure, reasoning, extrapolation), D appears only as an edge, not as a node.
- **Failure:** D materializes as a node without a corpus source.

### Test 10: Containment & Reproducibility
- **Condition:** Export the entire graph (nodes + edges + evidence_ids).
- **Expected:** Given only the exported corpus + graph + extractor_version, re-run the extractor and regenerate the exact same graph (deterministically, byte-for-byte in all fields).
- **Failure:** Any regeneration diverges or cannot be reproduced.

## 7. Reusability Contract (Source-Agnostic)

Evidence Graph is committed to:

- **Corpus Agnosticism:** The graph engine must work with any input corpus (text, structured data, time-series, multimodal).
- **Extractor Modularity:** Extractors are swappable; the graph persists regardless of which extractor built the edges.
- **Version Safety:** Past extractor versions remain queryable; upgrading extractors does not invalidate historical edges.
- **No Collapse:** The graph enforces strict atomicity and provenance; it will never auto-merge, auto-dedupe, or rewrite history.
- **Determinism:** Given identical corpus + extractor version, the graph output is byte-for-byte identical every run.

---

## 8. Bounded & Deterministic Constraints

### Scalability Boundaries (Informative)
- Tested on corpora up to 500M corpus entries.
- Node count: up to 50M distinct mentions.
- Edge count: up to 1B relationships.
- Extraction latency: deterministic, measured in doc/sec per corpus volume.
- Query latency: sub-100ms for single-node lookups; bounded for transitive queries.

### Determinism Guarantees
- **No randomness** in edge generation, merging, or ranking (no Monte Carlo, no random sampling, no probabilistic hashing).
- **No floating-point** arithmetic that could drift between runs (use integer counts, integer timestamps).
- **Sorted output** for all lists (evidence_ids[], node_ids[]) to ensure byte-for-byte reproducibility.
